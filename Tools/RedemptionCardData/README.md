# Redemption TCG Card Data Pipeline

This repository contains the data processing pipeline for mapping and verifying Redemption TCG core card data (`cards_extended.json`) against the official ORDIR category listings (`ORDIR_PDF_6.0.0.txt`).

## Pipeline Architecture

The pipeline is split into three deterministic Python scripts that must be run sequentially.

### 1. Extraction: `scripts/pipeline_01_extract_ordir_data.py`
**Purpose:** Reads the raw ORDIR PDF text, locates valid categories, and extracts every single card listed under those categories using structural scraping rules and strict markers.
**Output:** `data/ordir_extracted_raw.json`
*   **Key Logic:** Cleans typographical PDF noise while keeping parentheses intact. Relies on the "The following Redemption cards..." membership marker to know exactly when a category listing begins, avoiding false positives where rule texts are misidentified as lists of cards.

### 2. Fuzzy Mapping: `scripts/pipeline_02_fuzzy_map_cards.py`
**Purpose:** Matches the raw card names extracted by Pipeline 1 to the actual JSON card objects in `cards_extended.json`.
**Output:** `data/cards_extended_with_ordir_fuzzy.json` and `data/unmatched_ordir_entries.log` 
*   **Key Logic:** Uses fuzzy matching (`thefuzz`) to handle minor typos. To prevent "subset" false positives (where a short word like "Temple" blindly matches every single card with "Temple" in its name), it enforces a strict `fuzz.token_sort_ratio >= 80`. It also validates matches by intersecting Sets and Rarities using an aliasing engine (`mappings/alias_engine.py`).

### 3. Safety Verification: `scripts/pipeline_03_verify_mapped_data.py`
**Purpose:** Acts as a deterministic safety net. It scans the resulting mapped JSON data to identify any remaining logical mismatches or false positives that slipped past the fuzzy mapping.
**Output:** `data/verification_report.log`
*   **Safety Nets Included:**
    1.  **Alignment Checks:** Flags "Good" cards mapped to "Evil" categories and vice versa.
    2.  **Card Type Checks:** Flags cards lacking the correct XML type (e.g., a "Curse" category having a non-curse card).
    3.  **High-Category Anomaly:** Flags any card placed in an abnormally high number of categories (> 10).
    4.  **Reverse Category Logic (Book & Reference Checks):** Validates if a card in a "Genesis" category actually has a "Genesis" bible reference or name.
    5.  **Duplicate Card Checks:** Provides a basis for analyzing generic name matching within the "Duplicate Cards" section.

## How to Run

Ensure you have your virtual environment activated and the required dependencies installed (like `thefuzz`).

```bash
# Step 1: Extract ORDIR
python scripts/pipeline_01_extract_ordir_data.py

# Step 2: Map to JSON
python scripts/pipeline_02_fuzzy_map_cards.py

# Step 3: Verify the Matches
python scripts/pipeline_03_verify_mapped_data.py
```

## Reviewing the Results
Always check the `unmatched_ordir_entries.log` generated by Pipeline 02 to see which ORDIR cards could not be found in the JSON database (usually due to severe typos in the source text). 
After running Pipeline 03, check `verification_report.log` for anomalous assignments. Note that the Reverse Category Check (Rule B) may produce "False Positives" if a character from Genesis is quoted using a New Testament verse in the JSON data.
